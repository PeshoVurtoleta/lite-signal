--- 1.6.0 GAP REVIEW ---
1.6.0 adds createScope + describe and fixes the disposal crash. scope-torture
already covered createScope adoption + the crash fuzz. The UNCHECKED surface was
the read-only INTROSPECTION API (describe, nodeId, hasObservers, isTracking,
forEachObserver/Source/Owned, ownerOf, observeObservers) -- the substrate
lite-devtools / lite-studio build on. The whole suite exercised none of it.

introspect-torture closes that. Two load-bearing properties:
  1. WALK AGREEMENT -- forEachSource/Observer must match the real edge set and
     track dynamic rewiring (cross-checked vs the reference dep set + op-3/4 lane).
  2. THE ABA GEN-STAMP GUARD -- a descriptor captured before dispose+recycle must
     resolve to nothing, never the new resident. Broken, devtools would read a
     recycled node's edges as the old node's: silent data corruption. This guard
     is invisible to every value/wakeup/work oracle; introspect-torture is the
     ONLY scenario that catches its removal.

Note (self-correction recorded): observeObservers hooks are onConnect (0->1) and
onDisconnect (1->0) transitions, NOT per-add/remove. An early draft guessed
onObserverAdded/onObserverRemoved and failed; the engine was right, the test was
wrong. The scenario now pins the transition-only semantics explicitly.


--- 1.7.0 GAP REVIEW (flush-torture extended) ---
flush-torture already covered cross-strategy value convergence and .subscribe().
The UNCHECKED contracts found and added:
  1. VALUE-NEVER-DEFERS invariant: a computed pull is fresh WHILE effects are
     still deferred (the .d.ts's emphatic guarantee: only delivery defers). The
     suite previously checked effect convergence, never the synchronous pull a
     manual-mode consumer relies on.
  2. FLAG_QUEUED enqueue-dedup, counted via op-7. Run-count alone is MASKED by a
     second, execute-time dedup layer: a broken enqueue-dedup still yields 1 run
     while bloating the queue with 50 duplicate slots. Only op-7 (effect-enqueued)
     sees it. Deterministic-work lesson again.
  3. Invalid flushStrategy token throws (documented @throws; a silent fall-through
     to eager would hide a config typo in a real-time loop).
  4. Re-entrant flush (isFlushing guard), explicit flush INSIDE a batch draining
     mid-batch (pinned), and sab nested-batch flushing only at the outermost exit.

Mutation evidence: invalid-token and enqueue-dedup(op-7) are caught by
flush-torture uniquely. The isFlushing guard removal is caught by concurrent-storm
(reachable there via nested-flush/dispose-mid-flush), so flush-torture's
re-entrancy block is a focused pin rather than the sole catcher. The
value-never-defers invariant is a robust positive pin: the engine's pull path
compares dep VERSION independently of marking, so the value is correct even if
marking is skipped -- redundant correctness worth pinning.
