What this is: a local JavaScript port of the community reactivity benchmark
(js-reactivity-benchmark, transitive-bullshit's fork of milomg's "reactively"
benchmark). It is the cross-framework PERFORMANCE suite -- kairo propagation
shapes, the `mol` bench, the SolidJS `S` create/update micro-suite, the `cellx`
fan, and the `dyn` dynamic-component topologies. It complements benchmark.mjs
(lite-signal's own anti-DCE throughput harness in results.txt). Each engine runs
in its own cold process (FW=<engine>), so there is no cross-engine inline-cache
pollution or warm-heap borrowing.

1.5 -> 1.6 CHANGES the hot path (slightly). 1.5.1-beta.1 was byte-identical to 1.4
on propagation; 1.6.0-alpha adds two hook-gated fires: op 6 (`flush-pass-start`)
once per pass in `flushEffects`, and op 7 (`effect-enqueue`) inside `markDownstream`'s
inner loop when a dirty subscriber is enqueued. Each site is `if (mutationHook !==
null) mutationHook(op, ...)` -- branch-predicted-free when detached, allocation-
free when attached (opcode + two ints, no closure). The `flushPasses` counter on
`stats()` (the 12th key) is stat-only and advances only while a hook is attached.
The rest of the API-surface additions on this line -- `createScope` (adopting
lifecycle primitive), `getOwner` / `runWithOwner` (carried forward unchanged from
1.5.0-beta.2), and the two profiling harnesses (`harness/burst-dag.mjs`,
`harness/pull-stress.mjs`) -- do not touch propagation. Verified via sha256 over
`pullComputed` / `executeEffect` / `runCleanup` / `disposeNode` / `allocateLink` /
`severTail` / `createNode` / `createRoot` / `createScope` bodies vs 1.5.1-beta.1
(all identical); `markDownstream` and `flushEffects` are pinned by their new hashes.

Methodology note -- why median, not mean, and why isolated:
  On this 10-year-old 4-core host a single run occasionally spikes from a GC pause;
  median-of-10 removes that. Each engine runs in its own cold process so no engine
  pollutes another's inline caches or borrows its warm heap. The 10 raw runs sit
  under bench/bench-runs-reactive/run_1.txt ... run_10.txt and can be re-medianed
  independently.

VersionMatrix gate (harness/VersionMatrix/): the same-host cold-process regression
  gate that runs on prepublish. Four workloads map to the shapes above --
  reactive-graph-mix (kairo + mol pattern), deep-chain (kairo: deep / cellx pull),
  broadcast-fanout (BROADCAST from the propagation bench), and dynamic-dep-churn
  (dyn: dynamic / SELECTIVE DAG family). A candidate must clear both a fixed floor
  (frame.avg <=10%, p99 <=30% vs the never-regress baseline) AND the rolling
  baseline (frame.avg <=5%, p99 <=18% vs the previous published version); tighter
  on the anchor metric, generous on the jitter-prone p99s. The 1.5.0-beta
  identical-code guard (sha256 of the engine source per baseline; skip axes where
  the candidate is byte-identical) is still active -- on 1.6.0-alpha it will NOT
  skip vs the 1.5.1-beta.1 rolling baseline, because markDownstream / flushEffects
  legitimately changed. Details in harness/VersionMatrix/README.md.

Profiling harnesses (new in 1.6): `harness/burst-dag.mjs` and `harness/pull-stress.mjs`
  consume the new op 6/7 counters to characterise burst-flush shape and pull-mode
  recursion depth respectively. Standalone runners; also mountable as gate
  scenarios if desired. `npm run profile:burst` / `npm run profile:pull`.

Note: times from this host are a relative baseline; run on a quiet machine for
publishable absolute numbers. The relative ordering between libraries is what
matters. Prior baselines (1.5.0-beta, 1.4.0, 1.3.0, 1.2.2, 1.2.0, 1.1.5) are in
git history.
